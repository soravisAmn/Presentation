# slides builder


## เป้าหมาย
สร้างสไลด์ PowerPoint (.pptx) 

## แหล่งข้อมูลและลำดับเรื่อง
- **ใช้ข้อมูลจาก `draft#N\draft.md` เสมอ** (ฐานที่ `D:\Yo\Presentation\Presentation`) เป็นแหล่งเนื้อหาเดียว `draft.md` คือไฟล์ที่รวมโครงเรื่อง โดยเรียงตาม `input\content_order.txt` กับเนื้อหาครบทุกบทตาม `input\formatted\*.md` ไว้ในไฟล์เดียว และเก็บไว้ในโฟลเดอร์ draft#[N] ของรอบนั้นเพื่อให้รู้ว่าสไลด์แต่ละรอบใช้ข้อมูลอะไร ถ้าผู้ใช้ไม่บอกเลข N ให้ถามว่าสร้างรอบไหน ถ้าไม่มี `draft.md` ในโฟลเดอร์นั้นให้หยุดและแจ้งผู้ใช้ ไม่ต้องไปหยิบจาก draft อื่น ก่อนสร้างหรือแก้สไลด์ทุกครั้งให้อ่าน `draft.md` ใหม่ เพราะผู้ใช้อาจแก้ไฟล์ ห้ามสร้างสไลด์จากความจำหรือจากไฟล์ร่างเก่า
- สำหรับแหล่งข้อมูล, เนื้อหา, และลำดับเรื่อง ให้ใช้ไฟล์ `draft.md` เป็นหลัก ส่วนไฟล์อื่น (`formatted/`, โฟลเดอร์ draft ก่อนหน้า) ไม่เกี่ยวกับลำดับเรื่อง ให้ใช้แค่ draft.md ห้ามใช้ตัวอื่น เนื่องจาก `formatted/` เป็นผลลัพธ์จากขั้นตอนก่อนหน้านั้น ยกเว้น `resource/` เป็นแหล่งข้อมูลไว้ใช้แค่หารูปประกอบและแหล่งที่มาอย่างเดียว แต่ห้ามนำเนื้อหาจาก `resource/` มาใช้สร้างเนื้อหาในสไลด์
- ลำดับและชื่อบทมาจาก `draft.md` (ซึ่งเรียงตาม `content_order.txt`) ห้ามเปลี่ยนลำดับโดยไม่ถาม ถ้าอยากเสนอลำดับหรือเนื้อหาเพิ่ม ให้เขียนไว้ในไฟล์ .md แยก (เช่น `ข้อเสนอแนะ.md`) ไม่แก้สไลด์เอง
- ใน `draft.md` ชื่อบทเป็น `## ` ส่วนหัวข้อและรายการภายในบทเป็นเนื้อหาที่ใช้ย่อลงสไลด์ หนึ่งสไลด์ต่อหนึ่งประเด็นหลัก
- อ่านเนื้อหาจริงก่อนสร้างสไลด์ทุกครั้ง และเก็บแหล่งอ้างอิงตามเลข `[n]` ที่ติดอยู่ในต้นฉบับ
## ฟอนต์
- ใช้ฟอนต์ **TH Sarabun New** กับข้อความทั้งหมดในสไลด์ (หัวข้อ เนื้อหา ตาราง โน้ตผู้บรรยาย)
- ตั้งชื่อฟอนต์ให้ครบทั้งตัวอักษรไทยและละติน (latin, cs, ea) เป็น TH Sarabun New เพื่อไม่ให้ศัพท์อังกฤษในวงเล็บเปลี่ยนฟอนต์
- TH Sarabun New ตัวเล็กกว่าฟอนต์ทั่วไปที่ขนาดเท่ากัน ให้ตั้งขนาดใหญ่ขึ้นตามสัดส่วน (เช่น เนื้อหาตั้งแต่ 20 pt ขึ้นไป, หัวข้อตั้งแต่ 36 pt ขึ้นไป, หัวข้อย่อย 26 pt ขึ้นไป, ตาราง 18 pt ขึ้นไป) แล้วตรวจการล้นหน้าด้วยการเปิดดูทุกสไลด์
- ถ้าเครื่องที่ใช้เรนเดอร์ตรวจไม่มีฟอนต์นี้ ให้บอกผู้ใช้ว่าภาพตรวจเป็นฟอนต์ทดแทน การขึ้นบรรทัดอาจต่างจากในเครื่องจริง

## ข้อกำหนดจากผู้ใช้ (คงไว้)
- ข้อความบนสไลด์ใช้ภาษาไทยเป็นหลัก ศัพท์อังกฤษใส่ในวงเล็บ ใช้ภาษาวิชาการ ไม่ใช้ภาษาพูด ภาษาพูดเป็นหน้าที่ของผู้บรรยาย ใช้ศัพท์วิชาการเมื่อทำได้
- หัวข้อสไลด์ใช้หัวข้อ `###` ใน `draft.md` ตรงตัว (เปลี่ยนเฉพาะเลขนำหน้า) ไม่เขียนเป็นประโยคบอกสาระ สไลด์ปกใช้หัวเรื่อง `#` ของ `draft.md` และมีสไลด์คั่นบทใช้ชื่อบท `##`
- '####' ในไฟล์ draft.md นับเป็นหัวข้อย่อย แต่ไม่ต้องใส่หมายเลขหัวข้อย่อยในเนื้อหาสไลด์ถ้าไม่มีการเขียนไว้เอง เช่น ไม่ต้องเขียน 9.1.x 
- tag ที่ user กำหนด ได้แก่ <สไลด์/><\สไลด์>, <เนื้อหา/><\เนื้อหา>, <ตาราง/><\ตาราง>, <รูป/><\รูป> ซึ่ง user จะทำการเพิ่ม tag เหล่านี้เอง โดย user จะทำการเพิ่ม tag เหล่านี้เองลงใน  draft.md
- ถ้าจะเพิ่มสิ่งที่ผู้ใช้ไม่ได้ระบุ ให้ถามก่อน
- เมื่อค้นคว้าหรือสรุปข้อมูลเพิ่มเติม เช่น หารูปมาใส่ในสไลด์ ให้รวบรวมลิงก์และแหล่งที่มา บันทึกลง Excel พร้อมสรุปหัวข้อ

### tag สไลด์ปก
- "<สไลด์/><\สไลด์>" เมื่อเจอคำนี้ครอบข้อความส่วนใหน จะถือว่าข้อความนั้นรวมอยู่ใน 1 สไลด์ เช่น <สไลด์/>เนื้อหา1เนื้อหา2เนื้อหา3<\สไลด์> จะได้ 1 สไลด์ ประกอบด้วย 3 ประโยค หรือ <สไลด์/><เนื้อหา/>เนื้อหา1เนื้อหา2<\เนื้อหา><ตาราง/><\ตาราง><รูป/><\รูป><เนื้อหา/><\เนื้อหา><\สไลด์>> จะได้ 1 สไลด์ ประกอบด้วยเนื้อหา2เนื้อหา, ตาราง1ตาราง, รูป1รูป, และเนื้อหาอีก1เนื้อหา
- สามารถใส่ tag เนื้อหาซ้อนกันได้แบบ nested เนื้อหา เช่น <สไลด์/><เนื้อหา/><เนื้อหา/>เนื้อหาบรรยาย1<\เนื้อหา>เนื้อหาบรรยาย2<\เนื้อหา><ตาราง/><\ตาราง><รูป/><\รูป><\สไลด์>>

### tag เนื้อหาบรรยาย
- "<เนื้อหา/><\เนื้อหา>" เมื่อเจอคำนี้ครอบข้อความส่วนใหน ให้ทำการสร้างเนื้อหาบรรยายจากข้อความส่วนนั้น เช่น <เนื้อหา/>เนื้อหาบรรยาย1เนื้อหาบรรยาย2<\เนื้อหา>
- ถ้า user ใส่ <เนื้อหา/>เนื้อหา1<\เนื้อหา><เนื้อหา/>เนื้อหา2<\เนื้อหา> แปลว่าเนื้อหาแยกกันคนละกล่องข้อความ
- ถ้า user ใส่ <เนื้อหา/><เนื้อหา/>เนื้อหา1เนื้อหาบรรยาย1<เนื้อหา/>เนื้อหาบรรยาย2เนื้อหา2<\เนื้อหา> แปลว่าเนื้อหาบรรยาย1เนื้อหาบรรยาย2รวมกันเป็น 1 กล่องข้อความ

### tag ตาราง
- "<ตาราง/><\ตาราง>" เมื่อเจอคำนี้ครอบข้อความส่วนใหน ให้ทำการสร้างตารางจากข้อความส่วนนั้น เช่น 
<ตาราง/>
  ข้อความ1 | ข้อความ2 
  ข้อความ1 | ข้อความ2 
<\ตาราง>
หรือ
<ตาราง/>บทความยาวข้างใน<\ตาราง> ให้ทำการแปลงข้อความเป็นตาราง
- ก่อนตารางทุกครั้งต้องมีเกริ่นนำทุกครั้ง เขียนแค่ 1-2 บรรทัด
- ตารางทุกตารางต้องมีชื่อกำกับ ขึ้นต้นด้วยเลขตามบท เช่น "ตารางที่ 1.2"
### tag รูปภาพ
- "<รูป/><\รูป>" ให้ใส่รูปภาพจากข้อความส่วนนั้น โดยหารูปจาก `\draft#[N]\resource\[ชื่อบทใน draft.md]\` ถ้าในโฟลเดอร์ไม่มีข้อมูลให้ลองหาข้อมูลจากอินเตอร์เน็ตและหารูปจากการแคปหน้าจอแล้วนำมาใส่สไลด์ แต่ถ้าหาในอินเตอร์เน็ตไม่เจอแต่ถ้าเจอ "<รูป/>สร้าง<\รูป>" ให้สร้างรูปขึนมาที่เกี่ยวข้องกับหัวข้อนั้น
- รูปภาพทุกรูปภาพต้องมีชื่อกำกับ ขึ้นต้นด้วยเลขตามบท เช่น "รูปภาพที่ 1.2" พร้อมอธิบายประกอบภาพสั้นๆ และ พร้อมใส่ "ที่มา:" พร้อมแปะที่มา url หรือชื่อหนังสือที่อ้างอิงไว้ด้วย ตามหลัง
- ตัวเลขขึ้นบนสไลด์เฉพาะที่ตรวจแหล่งแล้ว ตัวเลขที่ยังไม่ตรวจให้อยู่ในโน้ตผู้บรรยายพร้อมเครื่องหมาย "รอตรวจแหล่ง" และเลขอ้างอิง `[n]` เก็บในโน้ตผู้บรรยาย ไม่ขึ้นบนสไลด์


## วิธีตัดข้อความลงสไลด์ (ตกลงไว้ตั้งแต่ draft#2)
- ข้อความบนสไลด์คือบรรทัดจาก `draft.md` ทั้งบรรทัด ไม่เรียบเรียงใหม่ ไม่แก้คำผิด ตัดได้เฉพาะ `**` เลขอ้างอิง `[n]` และป้ายกำกับ เช่น `[เพิ่มโดย Claude · …]`, `[เกลาจาก *…* · …]`, `[เรียบเรียงใหม่จากต้นฉบับ]`
- ข้อความที่มีป้าย "ความรู้ทั่วไป ยังไม่มีแหล่งอ้างอิง" ขึ้นสไลด์ได้ แต่ต้องใส่ "รอตรวจแหล่ง" ไว้ในโน้ตผู้บรรยาย ข้อความที่มีป้าย "ที่มา: …" ให้เก็บที่มาไว้ในโน้ต
- บรรทัดที่มีตัวเลขปริมาณ (ระยะ เปอร์เซ็นต์ จำนวน ราคา) ย้ายไปโน้ตผู้บรรยายพร้อม "รอตรวจแหล่ง" คำอย่าง "2 มิติ" "3 มิติ" ไม่นับเป็นตัวเลขปริมาณ
- เนื้อหาส่วนที่เกินแยกเป็นสไลด์ "(ต่อ)" ใช้เลขสไลด์เดียวกัน ไม่ย้ายไปโน้ต
- ตารางใน `draft.md` ขึ้นสไลด์ได้ ตั้งชื่อ "ตารางที่ N.M" ตามลำดับในบท แถวที่มีตัวเลขยังไม่ตรวจแหล่งย้ายไปโน้ต แถวที่ต้นฉบับยังไม่มีข้อมูลให้ระบุในโน้ตว่า "ยังไม่มีข้อมูลในต้นฉบับ"
- หลังสร้างต้องตรวจว่าทุกบรรทัดบนสไลด์พบใน `draft.md` และไม่มีป้ายกำกับหลงเหลือบนสไลด์หรือในโน้ต

## ไฟล์ที่ส่งมอบ
- `draft#N\draft#N.pptx`
- `draft#N\ข้อเสนอแนะ.md` ทุกครั้งที่ทำ draft ใหม่ ใส่ข้อเสนอลำดับบท เนื้อหาที่ควรเพิ่ม จุดที่ต้องตรวจใน draft.md และข้อจำกัดของ draft นั้น โดยไม่ลงมือแก้สไลด์เอง

## เกณฑ์เลือกเนื้อหาลงสไลด์
- เก็บ: สิ่งนั้นคืออะไรและให้ผลลัพธ์อะไร, ใช้เมื่อไรและข้อจำกัด, ความถูกต้องและต้นทุน
- ขั้นตอนเทคนิคเชิงลึกย้ายไปโน้ตผู้บรรยาย
- นิยามที่ซ้ำข้ามบท (เช่น DSM/DTM/DEM) ให้นิยามครั้งเดียวในที่ที่เหมาะที่สุด

## หลักการทำงาน
1. ดึงข้อมูลจากไฟล์ survey.md มาสร้างสไลด์ โดยใช้ข้อมูลที่ครบถ้วน ไม่ใช่แค่โครงเรื่อง
2. นิยามที่ซ้ำข้ามบท ให้นิยามครั้งเดียวในที่ที่เหมาะที่สุด แล้วบทที่เหลือให้เกริ่นสั้นๆ เพื่อเชื่อมโยงไปยังหัวข้อที่นิยามไปแล้ว
