# บทที่ 9 GIS และการบูรณาการข้อมูลเชิงพื้นที่

> ร่างเนื้อหาสไลด์ (ยังไม่จัดหน้า)

## สไลด์ 9.1 ข้อมูลสำรวจเข้าสู่ GIS ในรูปพิกัด ระดับ และรหัสจุด

- ข้อมูลจากเครื่องรับ GPS/GNSS และการรังวัดระดับ บันทึกผ่านแอปพลิเคชันภาคสนาม (เช่น ArcGIS Field Maps)
- ข้อมูลแต่ละจุดประกอบด้วยพิกัด (x, y) ค่าความสูง (z) และรหัสจุด (Point ID) นำเข้า GIS เป็นฟีเจอร์เวกเตอร์ (Feature Classes) หรือประมวลผลเป็นแบบจำลองพื้นผิวต่อเนื่อง
- เรขาคณิตสำรวจ (COGO) คำนวณระยะทางและทิศทางระหว่างจุด ใช้กำหนดขอบเขตเชิงกฎหมายและคำอธิบายแนวเขตที่ถูกต้อง
- การเชื่อมจุดสำรวจความแม่นยำสูง (Mass Points) กับฐานข้อมูล GIS ช่วยให้จัดเก็บ สืบค้น และคำนวณเรขาคณิตได้อย่างมีประสิทธิภาพ รองรับงานออกแบบโยธา การบริหารโครงสร้างพื้นฐาน คูคลองและลุ่มน้ำ

**อ้างอิงต้นทาง:** เลขท้ายประโยคในไฟล์ต้นทาง (เลขอ้างอิงติดกับข้อความ จึงยังไม่คัดลอกมาเพื่อกันอ่านผิด รอรายการแหล่งที่มาจากคุณ)

## สไลด์ 9.2 การวิเคราะห์ภูมิประเทศอาศัยแบบจำลองพื้นผิว

- แบบจำลองพื้นผิว: DEM/Surface Raster (เหมาะกับพื้นที่ขนาดใหญ่ ความถูกต้องขึ้นกับขนาดเซลล์) และ TIN (ประกอบด้วย Nodes, Edges, Faces ตามหลัก Delaunay ปรับความหนาแน่นตามความขรุขระ และแทรก Breaklines ได้)

**ตารางที่ 9.1 การวิเคราะห์ข้อมูลภูมิประเทศใน GIS**

| การวิเคราะห์ | ผลลัพธ์ | การใช้ประโยชน์ |
|---|---|---|
| Slope Analysis | อัตราการเปลี่ยนแปลงความสูงต่อระยะทางราบ (องศาหรือเปอร์เซ็นต์) | ประเมินความเสี่ยง เลือกพื้นที่เหมาะสม |
| Aspect Analysis | ทิศที่ความลาดชันหันไป | ประเมินรังสีอาทิตย์ ลม ฝน และจุลภูมิอากาศ |
| Hillshade Analysis | ภาพจำลองเงาภูมิประเทศ 3 มิติ | สื่อสารลักษณะภูมิประเทศ |
| Viewshed / Line-of-Sight | พื้นที่ที่มองเห็นและถูกบดบังจากจุดสังเกต | วางตำแหน่งและประเมินทัศนวิสัย |
| Vertical Profiles | ภาพตัดตามแนวเส้นทาง | งานตัดถนนและระบบสาธารณูปโภค |
| Hydrological Analysis | ทิศทางการไหล การสะสมน้ำท่า ขอบเขตลุ่มน้ำ จุดออกของน้ำ (Pour-points) | คาดการณ์น้ำท่วม บริหารจัดการน้ำ |
| Volume Calculations | ปริมาตรดินขุด-ดินถม ความจุอ่างเก็บน้ำ | งานวิศวกรรม |

**อ้างอิงต้นทาง:** เลขท้ายประโยคในไฟล์ต้นทาง (เลขอ้างอิงติดกับข้อความ จึงยังไม่คัดลอกมาเพื่อกันอ่านผิด รอรายการแหล่งที่มาจากคุณ)

## สไลด์ 9.3 การซ้อนทับชั้นข้อมูลสนับสนุนการตัดสินใจเชิงพื้นที่

- การซ้อนทับหลายชั้นข้อมูล (Multi-Layer Overlay) นำชั้นข้อมูลเฉพาะเรื่อง เช่น ดิน การใช้ประโยชน์ที่ดิน ธรณีวิทยา ความลาดชัน ที่อยู่ในระบบพิกัดเดียวกันมาประเมินความสัมพันธ์เชิงพื้นที่

**ตารางที่ 9.2 เปรียบเทียบเทคนิคการซ้อนทับ**

| เทคนิค | วิธีประมวลผล | ข้อสังเกต |
|---|---|---|
| Vector Overlay | คำสั่งเรขาคณิต: Union, Intersection, Difference | ซับซ้อนในการประมวลผล อาจเกิดโพลีกอนคลาดเคลื่อนขนาดเล็ก (Sliver Polygons) จากการดิจิไทซ์ไม่ตรงกัน |
| Raster Overlay & Map Algebra | ประมวลผลทีละเซลล์ ด้วยตัวดำเนินการทางคณิตศาสตร์ ตรรกศาสตร์ (AND, OR, NOT) และฟังก์ชันท้องถิ่น | ใช้กับโครงสร้างตารางแรสเตอร์ |

- GIS-MCDA: กระบวนการลำดับชั้นเชิงวิเคราะห์ (AHP) ของ Saaty เปรียบเทียบความสำคัญเป็นคู่ (Pairwise Comparison) บนสเกล 1–9 ร่วมกับความเห็นผู้เชี่ยวชาญ เพื่อกำหนดน้ำหนักของแต่ละปัจจัย
- การซ้อนทับแบบถ่วงน้ำหนัก (Weighted Overlay / WLC) คูณคะแนนของคุณลักษณะกับน้ำหนักปัจจัยแล้วซ้อนทับ เช่น การประเมินพื้นที่ศักยภาพน้ำใต้ดิน (Groundwater Potential Zones)

**อ้างอิงต้นทาง:** เลขท้ายประโยคในไฟล์ต้นทาง (เลขอ้างอิงติดกับข้อความ จึงยังไม่คัดลอกมาเพื่อกันอ่านผิด รอรายการแหล่งที่มาจากคุณ)

## สไลด์ 9.4 ฐานข้อมูลเชิงพื้นที่รองรับการใช้ข้อมูลร่วมกันหลายผู้ใช้

- การทำแผนที่: สัญลักษณ์เฉพาะเรื่อง ลำดับการวาด ความโปร่งแสง เส้นชั้นความสูง · Locators และ Geocoding แปลงพิกัด ที่อยู่ รหัสไปรษณีย์ หรือตำแหน่งตามระยะทางบนเส้นทางให้เป็นฟีเจอร์เชิงพื้นที่
- ระบบแฟ้มข้อมูลดั้งเดิม (Shapefiles) ไม่รองรับการแก้ไขพร้อมกันหลายผู้ใช้ ขาดการจัดการผ่าน SQL โดยตรง และมีข้อจำกัดด้านขนาดไฟล์

**ตารางที่ 9.3 องค์ประกอบของ Spatial Database**

| องค์ประกอบ | หน้าที่ |
|---|---|
| Spatial Data Types | เพิ่มประเภทข้อมูลรูปทรง เช่น Point, Line, Polygon |
| Spatial Indexing | ดรรชนีเชิงพื้นที่ (R-Tree, Quadtree) ใช้กล่องขอบเขตล้อมรอบ (MBR) สืบค้นพื้นที่ทับซ้อน แทน B-Tree เดิมที่จัดลำดับข้อมูล 2 มิติไม่ได้ |
| Spatial Functions | ฟังก์ชันเรขาคณิตมาตรฐาน OGC/SFSQL ผ่าน SQL เช่น ST_Intersects, ST_Contains, ST_Buffer, ST_Union |

- Enterprise Geodatabase: ใช้ RDBMS (PostgreSQL/PostGIS, Oracle, SQL Server) ร่วมกับ ArcSDE รองรับการจัดการหลายเวอร์ชัน (Multi-user Versioning) ให้หลายคนจัดการโทโพโลยีและแก้ไขข้อมูลพร้อมกันโดยข้อมูลไม่ขัดแย้งกัน

**อ้างอิงต้นทาง:** เลขท้ายประโยคในไฟล์ต้นทาง (เลขอ้างอิงติดกับข้อความ จึงยังไม่คัดลอกมาเพื่อกันอ่านผิด รอรายการแหล่งที่มาจากคุณ)
